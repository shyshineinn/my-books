# 开源与发布检查

## 仓库分工

- 后端与网页：[shyshineinn/my-books](https://github.com/shyshineinn/my-books)。
- 安卓改版：[shyshineinn/Mybooks](https://github.com/shyshineinn/Mybooks)，基于 Huangder 的 Lumi。
- 系统定位：单管理员、多设备，默认私有书库。不是多人账号系统。
- Web 定位为完整的书库管理后台，后续继续增强批量操作、元数据、附件、同步/设备与备份管理，不建设网页阅读器。
- 当前自建后端支持安卓阅读数据同步、书目增量与正文续传；与 WebDAV 是独立能力，具体范围见同步协议。

## 源码与署名

后端代码采用 GPL-3.0-only，许可证全文在根目录 `LICENSE`。
安卓保留上游 GPLv3、作者署名和全部第三方许可文件。
发布源码、容器或 APK 时检查 [第三方说明](../THIRD_PARTY_NOTICES.md)。
APK 对应的源码应能从明确的提交或源码归档获取；未提交的本地修改不能用旧上游源码冒充。
同一应用版本可能有多次构建，记录提交号及 APK SHA-256 来区分；不要擅自改应用版本。

## 本地检查

```sh
npm ci
npm run check:public
npm test
node scripts/check-public.mjs --history
git diff --check
```

扫描默认覆盖 Git 跟踪文件和未被忽略的新文件，不读取被忽略的真实书库。
`--history` 额外检查本地所有 Git 引用中的文本对象，不扫描远端尚未拉取的对象。
只报告文件名、行号与规则，不输出匹配值。
它检查部分令牌、私钥和私密文件名，不是完整的安全审计；二进制与大文件内容会跳过。
历史扫描发现问题时不要直接重写共享历史：先撤销有效凭据，再由维护者协调处理。

不要提交：数据库与备份、电子书和封面、个人心得、`auth.json`、Cookie、
`.env`、`local.properties`、设备令牌、APK 签名密钥，以及 APK 和构建缓存。
示例配置仅放占位值。正式 APK 作为发布附件提供，源码仓库不继续跟踪构建产物。
忽略规则不会删除已经存在于历史中的文件。

## 干净环境验收

1. 使用不含个人书库与本地密钥的新克隆，按 [自部署指南](SELF_HOSTING.md) 启动。
2. 全新书库应为空；创建管理员后可登录，未登录不能读取私有书目、封面、正文和心得。
3. 录入一本测试书，验证上传、下载、编辑、回收站恢复与安卓连接。
4. 验证冲突和明确删除事件，使用临时书库，不连接生产服务器做破坏性测试。
5. 在独立目录恢复备份，验证登录、文件与心得，不能只检查数据库完整性。

CI 已运行后端测试与当前源码检查；它不能代替 Docker 实际启动、安卓安装和备份恢复验收。

## GitHub 设置与发布

仓库所有者需在 GitHub 开启 Private vulnerability reporting，再确认 SECURITY.md 的私密入口可用。
提交前检查 diff 与暂存区；推送和创建 Release 由维护者明确发起。
发布说明列出能力范围、验证结果、数据库迁移版本、已知限制、源码提交与文件校验值。
本地检查成功不代表已上传代码、已发布或已部署。
